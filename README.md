# learn_A_language_packs

Language pack repository for the **learn_a_language** Flutter app
(see [learn_a_language](https://github.com/fl-tech-design/learn_a_language)).

This repository holds the **sources** for all course language packs and the
**tooling** that turns them into versioned, SHA-256-signed download packages.

## Why separate packs?

- The app bundle stays small – no language data ships with the app.
- Languages can be **installed and uninstalled** on demand by the user.
- Every pack download is **verified** against a SHA-256 checksum published in
  the central manifest before it is extracted.

## Repository layout

```
learn_A_language_packs/
├── language_dict/<lang>/      Dictionary JSONs per language (30 verb files,
│                              optionally extra categories such as adjectives)
├── audio/<lang>/              Audio files; relative paths are identical to the
│                              `audio` field entries inside the dictionary JSONs
├── grammar/grammar_<lang>/    Grammar documents (currently only German)
├── tools/build_packs.dart     Build pipeline: creates the ZIPs + manifest.json
├── dist/packs-v<version>/     Versioned, immutable pack ZIPs (committed)
├── manifest/manifest.json     Central manifest with SHA-256 sums + URLs
└── README.md
```

Language codes: `de`, `en`, `fr`, `es`, `el`, `ru`, `it`, `pt`.

## Pack format

Per language the build pipeline creates a ZIP named
`lal-pack-<lang>-<version>.zip` (e.g. `lal-pack-de-1.0.0.zip`) with the
following contents:

```
lal-pack-<lang>-<version>.zip
├── pack.json                  Pack metadata (see below)
├── language_dict/<lang>/      Dictionary JSONs
├── audio/<lang>/              Audio files
└── grammar/grammar_<lang>/    Grammar (only if present for that language)
```

### pack.json

```json
{
  "id": "de",
  "version": "1.0.0",
  "schema_version": 1,
  "contents": ["language_dict", "audio", "grammar"],
  "license": "See repository / app license"
}
```

- `id` – ISO 639-1 language code, also used for all file paths.
- `version` – pack version (matches the release tag).
- `schema_version` – format version of this pack.json (currently 1).
- `contents` – list of directories included in this pack.
- `license` – license/usage note for the contained data.

## Manifest (manifest.json)

Generated by `tools/build_packs.dart`; one entry per language:

```json
{
  "schema_version": 1,
  "version": "1.0.0",
  "packs": [
    {
      "id": "de",
      "version": "1.0.0",
      "url": "https://raw.githubusercontent.com/fl-tech-design/learn_A_language_packs/main/dist/packs-v1.0.0/lal-pack-de-1.0.0.zip",
      "size_bytes": 28123456,
      "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
      "min_app_version": "1.13.0",
      "contents": ["language_dict", "audio", "grammar"]
    }
  ]
}
```

Download URLs are **immutable**: they point to versioned paths under
`dist/packs-v<version>/` in this repository's `main` branch. Existing versions
are never overwritten – a new release lives in a new directory.

## Building

Requirements: Dart SDK plus `zip` and `sha256sum` (available on Linux/macOS).

```bash
dart run tools/build_packs.dart
```

The script writes the finished ZIPs to `dist/packs-v<version>/` (committed to
this repository) and regenerates `manifest/manifest.json`. Temporary staging
files live under `build/` (git-ignored).

## Versioning / Releasing

1. Bump `packVersion` in `tools/build_packs.dart` and re-run the build.
2. Commit `dist/packs-v<version>/`, the updated `manifest/manifest.json` and
   the script changes to the `main` branch.
3. The app reads the manifest from
   `https://raw.githubusercontent.com/fl-tech-design/learn_A_language_packs/main/manifest/manifest.json`.

## App integration (planned)

- On first start the app shows a notice that language packs must be installed
  before learning can begin.
- The language picker shows an **Install** button for languages whose pack is
  not installed yet, and an uninstall option for installed packs.
- Install = download ZIP → verify SHA-256 against the manifest → extract into
  the app documents directory.
- User data is never touched by install/uninstall operations.
